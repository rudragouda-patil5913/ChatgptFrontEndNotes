### Why were ES6 Classes introduced?

ES6 Classes were introduced to provide a cleaner and more familiar syntax for creating objects and implementing inheritance. Internally, JavaScript still uses prototypes. Classes are essentially syntactic sugar over the existing prototype-based inheritance model.

```
ES6 Classes were introduced to provide a cleaner, more readable, and organized syntax for object creation and inheritance. As JavaScript applications became larger, constructor functions and prototype assignments became harder to read and maintain.
Classes solved this by grouping everything together in one place.
```

### What is a constructor in a JavaScript class?

A constructor is a special method inside a class that is automatically executed when a new object is created using the new keyword. It is mainly used to initialize the object's properties. A class can have only one constructor.

```
class Employee {

    constructor(name) {
        this.name = name;
    }

    login() {
        console.log(this.name);
    }
}

const emp = new Employee("Rahul");
```

### What is extends?

The extends keyword is used to create a child class from an existing parent class. The child class automatically inherits the parent's properties and methods through JavaScript's prototype-based inheritance. It can also define its own additional methods and properties.

### What is super in JavaScript?

super is used in child classes to access the parent class. Inside a constructor, super() calls the parent constructor. Inside other methods, super.methodName() calls the corresponding parent method. In derived classes, super() must be called before accessing this because the parent constructor initializes the object.

### What is a Static Method?

A static method is a method that belongs to the class itself instead of its instances. It is called using the class name and is generally used for utility or helper functions that don't depend on object-specific data.

### What are private fields in JavaScript?

Private fields are class properties prefixed with #. They can only be accessed within the class that declares them. JavaScript enforces this restriction at the language level, preventing external code from reading or modifying those fields directly.

### What is Encapsulation?

Encapsulation is an OOP principle where an object's internal data is hidden, and access to that data is provided through controlled methods. This helps protect data integrity, enforce validation rules, and improve maintainability. In JavaScript, private fields (#) along with public methods are commonly used to implement encapsulation.

### Is JavaScript an object-oriented language or a prototype-based language?

JavaScript is a prototype-based object-oriented language. It supports object-oriented programming concepts such as encapsulation, inheritance, and polymorphism. Unlike languages like Java that use class-based inheritance, JavaScript uses prototype-based inheritance internally. Although ES6 introduced the class keyword, it is only syntactic sugar over JavaScript's prototype system.

### Inheritance

Inheritance is an OOP principle where a child class acquires the properties and methods of a parent class. It promotes code reuse, reduces duplication, and improves maintainability. In JavaScript, inheritance is implemented using prototypes, and the extends keyword provides a cleaner syntax for creating that relationship

### What's the relationship between Inheritance, Method Overriding and Polymorphism?

Inheritance establishes the parent-child relationship. Method Overriding allows the child class to provide its own implementation of a parent method. This overridden behavior enables Runtime Polymorphism, where the same method call produces different results depending on the object's actual type.

### Composition vs Inheritance?

Inheritance models an IS-A relationship, where a child class extends a parent class to reuse behavior. Composition models a HAS-A relationship, where an object contains other objects to achieve functionality. Modern software, including React, generally prefers composition because it provides greater flexibility, lower coupling, and easier maintenance.
```
Inheritance

class Vehicle {
  start() {
    console.log("Vehicle started");
  }
}

class Car extends Vehicle {
  drive() {
    console.log("Car is driving");
  }
}

const car = new Car();

car.start(); // Vehicle started
car.drive(); // Car is driving


Composition

class Engine {
  start() {
    console.log("Engine started");
  }
}

class Car {
  constructor() {
    this.engine = new Engine();
  }

  startCar() {
    this.engine.start();
    console.log("Car is running");
  }
}

const car = new Car();

car.startCar();

```

```
- Inheritance → IS-A relationship.
- Composition → HAS-A relationship.
- Use inheritance only when the relationship is natural.
- Use composition when an object is made up of other objects.
- Modern frontend frameworks (especially React) strongly favor composition.
```

### Why are classes called syntactic sugar?

Classes are called syntactic sugar because they provide a cleaner and more readable syntax over JavaScript's existing prototype-based inheritance system. Internally, JavaScript still uses constructor functions, prototypes, and the prototype chain. Classes do not introduce a new inheritance model; they simply make the existing one easier to use.

### Method Overloading
JavaScript doesn't support traditional method overloading like Java.
you can achieve similar behavior using optional parameters or rest parameters:

class Calculator {
  add(a, b, c) {
    if (c !== undefined) {
      return a + b + c;
    }

    return a + b;
  }
}

const calc = new Calculator();

console.log(calc.add(10, 20));      // 30
console.log(calc.add(10, 20, 30));   //60
