### What is an Execution Context?

Execution Context is the environment where JavaScript executes code. Every function invocation creates its own execution context containing variables, arguments, lexical environment, and the value of this. The JavaScript engine manages these execution contexts using the Call Stack by pushing them when execution begins and popping them once execution completes.

### Why did JavaScript introduce Execution Context?

JavaScript introduced Execution Context to provide an isolated workspace for every piece of executing code. Without separate execution contexts, variables, parameters, and this values from different function calls would interfere with each other. This isolation enables recursion, nested functions, closures, and predictable execution.

### Difference between Global Execution Context and Function Execution Context?

The Global Execution Context is created once when the JavaScript program starts and remains until the program finishes. A Function Execution Context is created every time a function is invoked and is destroyed once the function completes. Each function call receives its own independent execution context.

### Why is Memory Creation Phase required?

The Memory Creation Phase allows the JavaScript engine to know which variables and functions exist before execution begins. This enables features like function hoisting and predictable identifier resolution. Without this preparation phase, the engine would encounter references to identifiers before knowing they exist.

### Explain the Call Stack.

The Call Stack is a LIFO data structure that manages JavaScript execution contexts. Every function call creates a new execution context, which is pushed onto the stack. Once execution finishes, that execution context is popped, and control returns to the previous one.

### Why does JavaScript use a Call Stack?

The Call Stack allows JavaScript to keep track of the currently executing function and know where execution should return after a function completes. It also manages nested function calls and recursion in a predictable order.

### What causes "Maximum Call Stack Size Exceeded"?

This error usually occurs due to uncontrolled recursion or recursive function calls without a proper base condition. Every recursive call creates a new execution context, eventually exhausting the Call Stack.

### What is Hoisting?

Hoisting is JavaScript's behavior of registering variable and function declarations during the Memory Creation Phase before code execution begins. Function declarations are fully initialized, while var is initialized to undefined. let and const remain in the Temporal Dead Zone until initialization.

### Difference between var, let, and const.

var is function-scoped and is hoisted with an initial value of undefined, which can lead to unexpected behavior. let and const are block-scoped and remain in the Temporal Dead Zone until initialized. In modern JavaScript, I use const by default and let only when reassignment is required.

### What is the Temporal Dead Zone (TDZ)?

The Temporal Dead Zone is the period between entering a block scope and initializing a let or const variable. Accessing the variable during this period throws a ReferenceError, helping prevent accidental use before initialization.

### What is a Lexical Environment?

A Lexical Environment is a data structure that stores variables, function declarations, and a reference to the outer lexical environment. It is created based on where a function is defined, not where it is called, enabling lexical scoping and closures.

### What is the Scope Chain?

The Scope Chain is the mechanism JavaScript uses to resolve identifiers. If a variable is not found in the current lexical environment, JavaScript searches the outer lexical environment, continuing until it reaches the global scope or the variable is found.

### What are Closures?

A closure is created when a function retains access to variables from its outer lexical scope even after the outer function has finished execution. Closures are widely used for encapsulation, callbacks, event handlers, module patterns, and React Hooks.

### Why were Closures introduced?

Closures allow JavaScript functions to preserve state without exposing variables globally. This enables private data, modular code, callbacks, asynchronous programming, and stateful function behavior.

### Can Closures cause memory leaks?

Yes. If a closure unnecessarily retains references to large objects or DOM elements, the garbage collector cannot reclaim that memory. Proper cleanup and avoiding unnecessary references help prevent closure-related memory leaks.

### What is this?

this is a reference determined by how a function is invoked. Its value is established at runtime, not where the function is defined. Different invocation patterns such as default, implicit, explicit, and constructor calls determine its value.

### Difference between normal functions and arrow functions regarding this.

Normal functions receive their own this based on how they are called. Arrow functions do not have their own this; instead, they inherit it lexically from the surrounding execution context.

### Explain call, apply, and bind.

All three methods explicitly control the value of this. call() invokes the function immediately with individual arguments, apply() invokes it immediately with arguments passed as an array, and bind() returns a new function with this permanently bound without executing it immediately.

### What is an Object in JavaScript?

An object is a collection of key-value pairs used to model real-world entities and organize related data and behavior. Objects are reference types and form the foundation of JavaScript's prototype-based inheritance model.

### Difference between Object.freeze() and Object.seal().

Object.freeze() prevents adding, removing, or modifying properties. Object.seal() prevents adding or removing properties but still allows modification of existing writable properties.

### Difference between Shallow Copy and Deep Copy.

A shallow copy duplicates only the first level of an object, while nested objects remain shared by reference. A deep copy recursively duplicates nested objects, producing a completely independent copy.

### Why are JavaScript Objects reference types?

Objects are reference types because copying an object copies its reference rather than duplicating its contents. This makes object passing efficient but requires careful handling when mutating shared references.

### What is Garbage Collection?

Garbage Collection is JavaScript's automatic memory management process. It identifies objects that are no longer reachable from the application's root references and reclaims their memory.

### What is Reachability?

Reachability is the criterion used by the JavaScript garbage collector. An object is considered alive as long as it can be reached directly or indirectly from a root reference, such as the global object or active execution contexts.

### Why did JavaScript introduce Prototypes?

JavaScript introduced prototypes to enable memory-efficient code reuse. Instead of every object having its own copy of methods, objects can share methods through a prototype. This reduces memory usage while still allowing all objects to access common behavior.

### Difference between prototype and **proto**.

prototype is a property of constructor functions and classes that defines the shared methods for instances. **proto** is the internal reference of an object that points to the prototype it inherits from. In simple terms, functions have prototype, while objects have **proto**.

### What is the Prototype Chain?

The Prototype Chain is JavaScript's property lookup mechanism. If a property isn't found on the current object, JavaScript looks at its prototype, then that prototype's prototype, continuing until it reaches Object.prototype and finally null.

### Why is the Prototype Chain useful?

The Prototype Chain enables inheritance and code reuse without duplicating methods across objects. It allows JavaScript to share functionality efficiently while keeping objects lightweight.

### What is a Constructor Function?

A constructor function is a regular function invoked with the new keyword to create multiple similar objects. Before ES6 classes, constructor functions were the primary way to implement object-oriented programming in JavaScript.

### What does the new keyword do?

The new keyword creates a new object, links it to the constructor's prototype, creates a new execution context with this pointing to the new object, executes the constructor function, and finally returns the object.

### What is Object.create()?

Object.create() creates a new object whose prototype is explicitly set to the object passed as an argument. It is useful when you want direct prototype inheritance without calling a constructor.

### Why were ES6 Classes introduced?

ES6 classes were introduced to provide a cleaner and more familiar syntax for object-oriented programming. They improve readability, but internally JavaScript still uses prototype-based inheritance.

### Why are Classes called Syntactic Sugar?

Classes are called syntactic sugar because they provide a cleaner syntax over JavaScript's existing prototype system. They don't introduce a new inheritance model; they simply make prototype-based programming easier to write and understand.

### Difference between Inheritance and Composition.

Inheritance models an IS-A relationship, while Composition models a HAS-A relationship. Modern frontend applications, including React, generally prefer Composition because it offers greater flexibility and lower coupling.

### What is Polymorphism?

Polymorphism allows the same method to behave differently depending on the object invoking it. In JavaScript, this is commonly achieved through method overriding in inherited classes.

### Why does React prefer Composition over Inheritance?

React prefers Composition because components can be combined flexibly without creating deep inheritance hierarchies. Composition leads to lower coupling, better reusability, and simpler maintenance.

### What is Encapsulation?

Encapsulation is the practice of hiding internal implementation details while exposing only the necessary interface. In JavaScript, this can be achieved using closures, private class fields (#), or controlled getter/setter methods.

### What are Static Methods?

Static methods belong to the class itself rather than its instances. They are commonly used for utility functions or helper methods that don't depend on object-specific data.

### What is the DOM?

The DOM is a tree-like object representation of an HTML document created by the browser. Every HTML element becomes a node that JavaScript can access and modify dynamically.

### What is the BOM?

The Browser Object Model represents browser features such as the window, location, history, navigator, storage, and timers. The global window object is the root of the BOM.

### Explain the Browser Rendering Pipeline.

The browser parses HTML into the DOM Tree and CSS into the CSSOM Tree. These are combined to form the Render Tree. The browser then performs Layout (Reflow), Paint, and finally Composite to display pixels on the screen.

### Difference between Reflow and Repaint.

Reflow recalculates the layout because an element's size or position has changed. Repaint only redraws the visual appearance without changing layout. Reflow is more expensive because it often triggers a repaint.

### What is Event Bubbling?

Event Bubbling is the default browser event propagation mechanism where an event starts at the target element and propagates upward through its ancestors. It enables techniques such as Event Delegation.

### What is Event Capturing?

Event Capturing is the first phase of event propagation where the event travels from the document down to the target element. It can be enabled using the capture option in addEventListener().

### What is Event Delegation?

Event Delegation is a technique where a single event listener is attached to a parent element instead of multiple child elements. It relies on Event Bubbling to handle events from child elements efficiently.

### Difference between event.target and event.currentTarget.

event.target is the element that originally triggered the event, while event.currentTarget is the element whose event listener is currently executing.

### Difference between LocalStorage, SessionStorage and Cookies.

LocalStorage stores data permanently until explicitly removed. SessionStorage stores data only for the current browser tab or session. Cookies are small pieces of data that are automatically sent with HTTP requests and are commonly used for authentication and session management.

### When would you use IndexedDB instead of LocalStorage?

IndexedDB is suitable for storing large, structured, or offline data, whereas LocalStorage is best for small key-value pairs such as user preferences or themes.

### Which browser storage would you choose for authentication?

For authentication, I generally prefer HttpOnly Secure Cookies because they are inaccessible to JavaScript, reducing the risk of XSS attacks. LocalStorage may be suitable for non-sensitive client-side preferences, but sensitive authentication tokens are usually safer in properly configured cookies.

### Why is JavaScript single-threaded?

JavaScript was designed as a single-threaded language because it was originally created for browsers, where multiple threads modifying the DOM simultaneously could cause race conditions and inconsistent UI state. A single-threaded model ensures predictable execution. Asynchronous operations are handled by browser APIs and coordinated through the Event Loop.

### What is the Browser Runtime?

The Browser Runtime is the environment that executes JavaScript. Besides the JavaScript engine, it provides APIs such as timers, networking, DOM events, rendering, and storage. JavaScript delegates asynchronous work to the browser, which notifies the engine when the work completes.

### What are Web APIs?

Web APIs are browser-provided features that allow JavaScript to perform asynchronous operations such as timers, network requests, DOM events, and storage. They are not part of the JavaScript language itself.

### Explain the Event Loop.

The Event Loop continuously monitors the Call Stack and task queues. When the Call Stack becomes empty, it moves pending tasks into the Call Stack for execution. It processes all Microtasks before handling the next Macrotask.

### Difference between Microtask Queue and Callback Queue.

The Microtask Queue contains high-priority tasks such as Promise callbacks and queueMicrotask(). The Callback Queue (Macrotask Queue) contains tasks like setTimeout() and DOM events. After the Call Stack becomes empty, the Event Loop executes all Microtasks before processing the next Macrotask.

### Why does Promise.then() execute before setTimeout(0)?

Promise callbacks are scheduled in the Microtask Queue, while setTimeout() callbacks are placed in the Callback Queue. The Event Loop always processes all Microtasks before taking the next Macrotask.

### What is Run-to-Completion?

Run-to-Completion means that once JavaScript starts executing a function, it continues until that function finishes. The Event Loop never interrupts a running execution context.

### Why were Promises introduced?

Promises were introduced to solve Callback Hell and improve asynchronous code readability, composability, and error handling. They allow developers to chain asynchronous operations in a cleaner and more maintainable way.

### Explain Promise States.

A Promise has three states: Pending, Fulfilled, and Rejected. It starts in the Pending state and eventually settles as either Fulfilled or Rejected. Once settled, its state cannot change.

### What is Promise Chaining?

Promise Chaining allows multiple asynchronous operations to execute in sequence by returning a new Promise from each .then() call. This keeps asynchronous workflows readable and manageable.

### Difference between Promise.all() and Promise.allSettled().

Promise.all() fails immediately if any Promise rejects and returns results only if all succeed. Promise.allSettled() waits for every Promise to settle and returns the status of each one, making it suitable for partially successful operations.

### Difference between Promise.race() and Promise.any().

Promise.race() returns the first settled Promise, whether fulfilled or rejected. Promise.any() returns the first fulfilled Promise and ignores rejections unless every Promise fails.

### Why does Promise.all() fail fast?

Senior Answer

Promise.all() is designed for scenarios where every operation is required. If one Promise fails, the combined result is no longer valid, so it rejects immediately instead of waiting for the remaining operations.

### Why is Promise.allSettled() useful?

Promise.allSettled() is useful when operations are independent. It allows successful results to be processed even if some requests fail, improving user experience in dashboards and widget-based applications.

### What does an async function return?

An async function always returns a Promise. If a normal value is returned, JavaScript automatically wraps it using Promise.resolve().

### What does await do?

await pauses the execution of the current async function until the awaited Promise settles. It does not block the JavaScript engine or the Event Loop.

### Does await block JavaScript?

No. await pauses only the current async function. The JavaScript engine remains free to execute other tasks while waiting for the Promise to resolve.

### Sequential vs Parallel API calls.

Sequential execution is appropriate when one request depends on the result of another. Parallel execution using Promise.all() is preferred when requests are independent because it reduces overall waiting time.

### Why use try-catch with Async/Await?

try-catch provides synchronous-looking error handling for asynchronous code. It makes complex workflows easier to read and centralizes error management.

### When would you choose Promise.all() over Sequential await?

I choose Promise.all() when requests are independent and can execute concurrently. I use sequential await only when later operations depend on earlier results.

### What is Destructuring?

Destructuring provides a concise syntax for extracting values from arrays or properties from objects. It improves readability and reduces repetitive property access.

### Difference between Rest and Spread.

Spread expands arrays or objects into individual elements or properties. Rest collects multiple values into a single array or object. The same ... syntax performs different roles depending on context.

### Difference between || and ??.

|| treats every falsy value as missing, including 0, false, and an empty string. ?? only treats null and undefined as missing, making it safer for default values.

### Why use Map instead of Object?

Map supports keys of any type, preserves insertion order, and provides optimized APIs for frequent insertions, deletions, and lookups. It is often preferable when keys are dynamic.

### Difference between for...in and for...of.

for...in iterates over property keys, while for...of iterates over iterable values such as arrays, strings, and Maps.

### When should APIs be retried?

Retry only transient failures such as network errors or 5xx server responses. Avoid retrying client errors like 400, 401, 403, or 404 because retrying won't fix the request.

### What is Exponential Backoff?

Exponential Backoff increases the delay between retry attempts, giving the server time to recover and preventing retry storms during outages.

### Why add Jitter?

Jitter introduces randomness into retry delays so that many clients do not retry at the same moment, reducing traffic spikes.

### What is Idempotency?

Idempotency ensures that repeating the same request produces the same result without creating duplicate side effects. It is commonly used in payment APIs through idempotency keys.

### What is AbortController?

AbortController allows applications to cancel in-flight network requests that are no longer needed, improving performance and preventing stale responses.

### Debounce vs AbortController.

Debounce prevents unnecessary requests from being sent. AbortController cancels requests that have already been sent but are no longer relevant. They solve different problems and are often used together.

### Why use Limited Concurrent Requests?

Limiting concurrent requests prevents overwhelming the browser, network, or server while maintaining good throughput and predictable resource usage

### Why not retry every API?

Not every failure is transient. Retrying client errors wastes resources and may produce incorrect behavior. Retry logic should be based on error type and business requirements.

### What is EventEmitter?

EventEmitter is a pattern that enables event-driven communication within an application by allowing components to emit events and other components to subscribe to them.

### What is Pub/Sub?

Publisher–Subscriber introduces a broker between publishers and subscribers, enabling loosely coupled communication that scales well across large or distributed systems.

### EventEmitter vs Pub/Sub.

EventEmitter is generally used for communication within the same application. Pub/Sub introduces a broker, allowing publishers and subscribers to remain completely independent.

### Why use EventEmitter?

EventEmitter reduces coupling between modules by allowing components to react to events without directly calling one another.

### Retry failed uploads or stop everything?

If uploads are independent, continue uploading the remaining files and retry only the failed ones. If operations are dependent, stop the workflow to avoid inconsistent state.

### Promise.all() or Promise.allSettled() for a dashboard?

If dashboard widgets are independent, use Promise.allSettled() so successful widgets can render even when some APIs fail.

### Should every request use AbortController?

No. Use AbortController when older requests become irrelevant, such as search or navigation. Avoid cancelling critical business operations like payments without carefully considering the workflow.

### Why use Debounce?

Debounce delays execution until user activity stops, reducing unnecessary work and API requests.

### Why use Throttle?

Throttle limits how frequently an operation executes, making it ideal for scroll, resize, and mouse movement events.

### Why use Skeleton Loading?

Skeleton loading improves perceived performance by immediately showing the structure of the page while data is loading.

### Why use Lazy Loading?

Lazy loading delays loading of non-critical resources until they are needed, improving initial page performance.

### Why use Caching?

Caching reduces repeated network requests, improves response time, and lowers server load by reusing previously fetched data.

### How do you optimize a search feature?

I combine Debounce, AbortController, caching, loading indicators, and efficient backend APIs to reduce unnecessary requests while providing fast feedback.

### How would you optimize large file uploads?

I would upload files using limited concurrency, retry transient failures with exponential backoff, and allow retrying only failed files.

### How do you improve frontend performance?

I minimize unnecessary rendering, lazy load resources, batch updates, reduce reflows, cache data, and optimize network requests.

### What makes a good frontend engineer?

A good frontend engineer balances correctness, performance, maintainability, accessibility, and user experience while making thoughtful engineering trade-offs.

### What is the most important thing you've learned about JavaScript?

JavaScript is more than a programming language—it's an execution model. Understanding how the engine, browser runtime, event loop, prototypes, closures, and asynchronous behavior work together is far more valuable than memorizing syntax because it allows you to solve real engineering problems confidently.
