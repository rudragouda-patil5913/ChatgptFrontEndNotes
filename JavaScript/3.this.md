### "this" keyword

The value of this is determined by how the function is invoked.

## Default Binding

```
function show() {
    console.log(this);
}
show();
```

## Implicit Binding

When a regular function is called as a method of an object, the object immediately before the . becomes the this value.

```
const user = {
    name: "Rudra",
    show: function () {
        console.log(this);
    }
};

user.show();
```

#### Interview Trap

```
const user = {
    name: "Rudra",
    show: function () {
        console.log(this.name);
    }
};

const fn = user.show;
fn();
```

```
Many people look at where the function was originally defined:
user.show
and say:

"this should be user."
❌ Wrong.
We care about the actual invocation:
fn();

There is no object before fn().
Therefore, the call is a plain function call → Default Binding.
This is one of the most important this concepts.
```

## Explicit Binding — call(), apply(), bind()

#### This is where we explicitly tell JavaScript which object should become this.

```
  function greet() {
    console.log(this.name);
  }

  const user = {
    name: "Rudra"
  };

  greet.call(user);

  Look at the call:
  greet.call(user);

  We're explicitly saying:
  "Execute greet with user as its this."

  Conceptually:
  greet.call(user)
      ↓
  this = user
      ↓
  execute greet

  So this is called:
  Explicit Binding
```

### Example of bind

```
const person = {
name: "Rudra",
    greet() {
        console.log(this.name);
    }
};

setTimeout(person.greet, 1000);
```

```
The function is eventually called like a normal callback.
The original relationship:
person.greet
doesn't automatically travel with the function.

So we can do:
setTimeout(person.greet.bind(person), 1000);
Now:

person.greet
    ↓
bind(person)
    ↓
new function
    ↓
callback()
    ↓
this → person

This is one of the most common practical uses of bind().
```

### New binding

#### new creates a new object and makes this inside the constructor refer to that newly created object.

```
function Person(name) {
  this.name = name;
}

const person1 = new Person("Rudra");
const person2 = new Person("Sam");

Let's slow this down because this is an important interview concept.
When you do:

const person1 = new Person("Rudra");

conceptually, JavaScript performs several steps.

- Step 1 — Create a new object
              {}
- Step 2 — Set this to that new object
        this ─────► {}
- Step 3 — Execute the constructor function
        this.name = name;
        this ─────► { name: "Rudra"}
- Step 4 — The constructed object becomes the result of new
        person1 ─────► {
            name: "Rudra"
        }

Then:
const person2 = new Person("Sam");
creates another object:

person1 ─────► { name: "Rudra" }

person2 ─────► { name: "Sam" }

They are completely separate objects.
```

---

```
function test() {
  console.log(this);
}

const obj = {
    test: test
};

const fn = obj.test;

test(); ---> default
obj.test();--->implicit
fn();---> default
test.call(obj); --> explicit
new test(); ---> new binding

const fn = obj.test;
doesn't preserve the obj relationship.
fn is simply another reference to the same function object.
fn() is a plain function call → Default Binding.

```

### Arrow functions don't have their own this

#### Arrow functions do not create their own this binding.

Instead, an arrow function gets this lexically from its surrounding context.

```
const person = {
  name: "Rudra",
  greet() {
    setTimeout(() => {
    console.log(this.name);
    }, 1000);
  }
};
```

```
person.greet()
      ↓
regular function
      ↓
this = person
      ↓
setTimeout callback
      ↓
arrow function
      ↓
doesn't create its own this
      ↓
uses surrounding this
      ↓
    person
```

This is one of the biggest practical reasons arrow functions are useful for callbacks.

`const arrow = () => {console.log(this)};`

It does not have its own this binding.

Therefore these don't change its this:

- arrow();
- obj.arrow();
- arrow.call(obj);
- arrow.apply(obj);
- arrow.bind(obj);

This is an important interview point.
call, apply, and bind cannot provide an arrow function with its own this.
The arrow continues using its surrounding this.
