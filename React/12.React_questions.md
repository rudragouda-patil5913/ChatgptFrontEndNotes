### Why was React introduced?

React was introduced to simplify building complex, interactive user interfaces. As applications grew larger, manually manipulating the DOM became difficult, error-prone, and hard to maintain. React introduced a declarative programming model where developers describe the desired UI, and React efficiently updates the DOM behind the scenes.

### If React didn't have a Virtual DOM, would React still be useful? Why?

Yes. React would still be useful even without the Virtual DOM because its biggest contribution is its declarative, component-based architecture. Developers describe what the UI should look like instead of manually manipulating the DOM. This makes large applications easier to build, maintain, and reason about. ### What is Virtual DOM?

The Virtual DOM is a lightweight JavaScript object representation of the Real DOM. React updates the Virtual DOM first, compares it with the previous version, identifies the differences, and then updates only the necessary parts of the Real DOM.

### Why did React introduce Virtual DOM?

The Virtual DOM was introduced to efficiently determine what changed in the UI before updating the Real DOM. It allows React to batch updates and minimize unnecessary DOM manipulations, making complex UI updates easier to manage and often more efficient.

Virtual DOM is a lightweight JavaScript representation of the UI. When application state changes, React creates a new Virtual DOM, compares it with the previous version through the diffing algorithm, and updates only the affected parts of the Real DOM. This approach simplifies UI programming and helps reduce unnecessary DOM updates in complex applications.

### Is Virtual DOM faster?

Not always. Virtual DOM introduces comparison overhead. Its primary advantage is making complex UI updates predictable and efficient by reducing unnecessary Real DOM manipulations.

### Why compare? when we can update Real DOM?

React compares the old Virtual DOM with the new Virtual DOM because a state change doesn't necessarily mean every part of the UI has changed. By comparing both trees, React can identify exactly which nodes are different and update only those parts of the Real DOM. This minimizes unnecessary DOM manipulations and keeps UI updates predictable.

### Comparing two objects is cheaper than updating real DOM?

The Virtual DOM is a lightweight JavaScript object that exists entirely in memory. Comparing two JavaScript objects is generally a CPU operation and is relatively inexpensive. Updating the Real DOM, however, may trigger the browser's rendering pipeline, including layout (reflow), paint, and compositing, which are much more expensive operations. React performs a comparison first so that it updates only the DOM nodes that actually changed, reducing unnecessary rendering work.

### Why did React introduce components?

Components allow complex interfaces to be broken into smaller, independent units with their own UI and behavior. This improves maintainability, reuse, testing, and separation of concerns. React then uses composition to combine these smaller units into larger interfaces, which makes large applications easier to reason about and evolve.

### Props vs normal function parameters?

Conceptually, Props are inputs to a React component just like parameters are inputs to a JavaScript function. The difference is that React provides those values when rendering the component, and Props should be treated as read-only so that component data flow remains predictable.

### What is State and why does React need it?

State represents data that React preserves across renders and that can affect the rendered UI. When state is updated, React schedules a new render so the UI can be recalculated from the latest state. This allows developers to update application data declaratively instead of manually synchronizing data with DOM elements.

### What does re-rendering mean in React?

A re-render means React executes the component again to calculate a new UI description based on the latest props and state. React then reconciles that result with the previous one and commits only the necessary DOM changes. Therefore, a component re-render does not necessarily mean the Real DOM is updated or that the browser repaints.

### Conditional rendering?

Conditional rendering means rendering different UI based on the current props, state, or application conditions. React doesn't introduce a special conditional language; we use normal JavaScript constructs such as if, ternaries, and logical operators to decide which React elements should be returned.

### Why does React need keys?

Keys give elements stable identity within a list. During reconciliation, React uses them to determine which items were added, removed, moved, or preserved. Stable keys allow React to preserve the correct component state and efficiently update dynamic lists.

### Controlled vs Uncontrolled Components?

In a controlled component, React state is the source of truth and the input value is updated through state and event handlers. In an uncontrolled component, the DOM maintains the input's value and React typically accesses it using a ref when needed. I choose based on whether the application needs React to actively synchronize and respond to the input value.
